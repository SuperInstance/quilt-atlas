# quilt-atlas

**The living map of the SuperInstance account.** One scheduled workflow re-inventories every repo every 6 hours: families, motion, CI coverage on the moving frontier — and commits the diff. The map only grows truer; nothing is deleted.

## Why an atlas

The account crossed 300 repos and multiple agent lanes push daily. No single lane can hold the whole graph in its head anymore — and per the stone standard, a *stranger* should be able to see what this fleet is and whether it's alive. The atlas is that stranger's first receipt: counts, families, motion, and CI coverage, regenerated by the same account it describes.

**v2 (53-e):** a repo whose *name* matches nothing gets a second chance via its *description* — case-insensitive substring scoring against a small synonym table per family (e.g. quilt: "reactive cell", "cell runtime", "sheet"; jev: "living model", "jepa"; fleet: "agent", "lane", "receipt"), highest score wins, ties broken by family precedence. Every repo records its evidence — `[family, stage, matched keywords, language]` — in `atlas.json` → `classification`, so every assignment is auditable. Honesty laws: families are name-then-description classified (imperfect on purpose, stated in atlas.json notes); CI is probed only on the top-motion slice — absence elsewhere is **UNMEASURED**, never reported as zero; the page count is receipted, so a bounded run can never masquerade as a full inventory.

```bash
GITHUB_TOKEN=... node scripts/build_atlas.mjs   # regenerates atlas.json + README block
```

Or let the schedule do it: `atlas.yml` runs every 6h and on demand.
