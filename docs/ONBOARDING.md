# quilt-atlas — Agent Onboarding
> Zero-shot entry point. Clone → competent in ~10 minutes.

## Identity (2 sentences)

quilt-atlas is the living map of the SuperInstance GitHub account (~5,168 repos as of the
2026-10-04 run): one zero-dependency Node script (`scripts/build_atlas.mjs`), run on a 6-hour
schedule by `.github/workflows/atlas.yml`, re-inventories every repo via the GitHub REST API,
classifies it into fleet families with per-repo evidence, probes CI coverage on the
most-recently-pushed slice, and commits the diff to `atlas.json` plus the generated README
block. The repo also hosts the account's research studies (`studies/`) and the SEED DNA
catalog (`seed-dna/`), which are appended to, never deleted.

## Why it exists (the fleet problem it solves)

The account crossed 300 repos in its early waves and is now past 5,000, with multiple agent
lanes pushing daily. No single lane can hold the whole graph in its head, and per the stone
standard a *stranger* should be able to see what this fleet is and whether it is alive
without trusting anyone's word. The atlas is that stranger's first receipt: counts, families,
motion, and CI coverage, regenerated by the same account it describes. Built across waves
52–55 (tasks 52-a/53-e/54-c/55-c: v1 name classifier → v2 description classifier → v3
Link-header pagination → qthe keyword audit), extended as the studies home from wave 71
onward (DEEP-STUDY-71, the wave-72 battery, the MECHANICAL M1–M5 program in waves 74–78).

## Verify it works (exact commands)

```bash
# 0. No dependencies to install — the builder is zero-dep Node (>= 18 for global fetch;
#    CI pins Node 20). Sanity-check the syntax without any credentials:
node --check scripts/build_atlas.mjs

# 1. Inspect the last scheduled run's output (this IS the verification — the map is a
#    receipt of its own last run):
jq '.generated_at_utc, .total_repos, .pages_fetched, .pagination_cap_hit' atlas.json
jq '.families' atlas.json

# 2. Regenerate the map yourself. REQUIRES a GitHub token (any token with public-repo
#    read; in CI this is the workflow's own secrets.GITHUB_TOKEN). Without a token the
#    GitHub API returns 401 and the run fails by design — there is no offline mode:
GITHUB_TOKEN="$(gh auth token)" node scripts/build_atlas.mjs
#    Expected console output:
#    pagination: <N> pages, <M> repos, hard-cap-hit=false
#    atlas built: <M> repos across <N> pages, 24 CI-probed, families other=... · fleet=... · ...
#    stages: none=... · description=... · name=...
#    Side effects: rewrites atlas.json and the README block between the ATLAS markers.

# 3. Produce the keyword-audit dump (env-gated, off by default in scheduled runs):
ATLAS_DUMP=/tmp/atlas-dump.json GITHUB_TOKEN="$(gh auth token)" node scripts/build_atlas.mjs
```

Nothing here needs any credential beyond a GitHub token; the workflow runs on the public
schedule and its commits (`atlas: scheduled regen <ts>`, author "quilt-atlas bot") are the
standing proof that the pipeline works unattended. If you cannot run step 2, atlas.json at
HEAD is itself the receipt of the most recent scheduled run.

## The things that will bite you (gotchas)

- **The builder writes `README.md` relative to the current working directory.** Run it from
  the repo root, or it will create/patch a README somewhere else and the ATLAS markers will
  not be found (it would then *append* a second block rather than replace).
- **No token, no run.** The script throws on the first non-OK GitHub response. There is no
  cached/offline fallback; the error is honest and immediate.
- **Do not hand-edit inside `<!-- ATLAS:BEGIN ... ATLAS:END -->`.** The next scheduled run
  will replace whatever is between the markers. Prose above the block is yours; the block is
  the machine's.
- **"other" is honest residue, not failure** — 2,717 of 5,168 repos are unclassified by
  design (name-then-description matching, deliberately imperfect). Absence of CI data on a
  repo means **UNMEASURED** (only the top-24 motion slice is probed), never zero.
- **The classifier is precedence-ordered**: `jev > latent > moth > qthe > quilt > fleet`.
  A repo named with two family keywords lands in the earlier family. The stability rule
  (receipted in `atlas.json → notes`): no unforced reclassification — audited residuals
  (e.g. ~2% of desc-stage qthe matching "canonical" as an adjective) are *priced, not fixed*.
- **Family counts move under your feet.** Parallel lanes push continuously (the wave-49/50
  journal observed pushes landing *during* a census session). Any number you quote should
  carry the `generated_at_utc` of the run that measured it.
- `studies/*.md` cite artifacts under `scripts/` and `outputs/` of the *workspace* (the
  wave harness root), not of this repo; the repo holds the study docs and data copies under
  `studies/data/`. Check both places when chasing a receipt.

## Current frontier (what is open right now)

- The qthe synonym audit's receipted residual (~2% adjective-collision, e.g.
  `substrate-opposites`) is priced, not fixed — the stability rule forbids unforced
  reclassification; a future lane may add a negative-keyword stage instead.
- No synonym audit exists yet for the other description-stage families (moth=3, latent=5
  are too small to bother; quilt=47 and jev=28 are candidates).
- The studies layer grows per wave (M1–M5 concluded through wave 78; the mechanical-learning
  program's next round, and any new standing instrument like `promise-census`, lands here
  append-only).
- The generated block still reports only the top-24 CI slice; extending coverage honestly
  (e.g. a sampled second slice, receipted like the audits) is an open design question.
